Two hidden rules in React

Either rule is fine on its own. Together, they make every widget wait.

Rule 1: the waiter always says “one moment” first

A React.lazy component always suspends on its first render, even if its code is loaded. It calls import() only then and gets the module through a promise that always resolves after that render. Calling import() early doesn't help: lazy still starts its own import and suspends once.

Rule 2: dishes are served together, 300 ms later

🍲 A ready at 20
🍲 B ready at 60
🍲 C ready at 150
0150300 ms

After a fallback appears or is replaced anywhere on the page, React waits 300 ms before revealing suspended content (FALLBACK_THROTTLE_MS). The docs say “at most once every 300ms, measured from the last reveal.” It's intentional, to prevent flicker. Issue #31819 asks for it to be configurable; the maintainers have kept it fixed.

Together: every widget showed its placeholder for at least 300 ms, however fast its code arrived. Because the timer is page-wide, widgets appeared in batches.
