Fix #2 · the one that held up

Skip the waiter. Bring the dish yourself.

Widgets no longer suspend while their code loads. The placeholder is shown as ordinary content, and a normal state update swaps in the widget when its code arrives. Nothing suspends, so the 300 ms rule never kicks in.

🛟 Keep the safety netsKeep Suspense and the error boundary. They still catch failed imports, and any suspension if React's private fields change.
💥 Failed load?The widget still renders, so its error boundary can show the failure.
🪟 Already loaded?Ready right away, including when React loaded it on its own, e.g. in a picture-in-picture window.
🚀 Startup doesn't waitLoading still starts before the first render, but the app no longer waits for it.
🧩 One by oneWidgets now appear one at a time instead of in a batch. That's fine: every frame has a fixed grid size, so nothing shifts.
🔐 Same trick, elsewhereThe permission check used by Timer, Countdown, Pomodoro, History and Bookmarks was a suspending query. It's now an ordinary query.
