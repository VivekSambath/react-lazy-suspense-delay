Code ready aanaalum, reveal udane nadakkaadhu

Why the wait? React suspended content-ah at most once every 300 ms thaan reveal pannum, last fallback kaattuna time-la irundhu (FALLBACK_THROTTLE_MS). Flicker avoid panna intentional-ah vechirukkanga. Idhu throttle, ella component-kum fixed delay illa: code 300 ms-ku apparam vandha, extra wait illa.
Transition vs normal: already visible content-ah transition update pannaa, React old content-ah screen-la vechchikkum (fallback flash illa). Aana first time mount aagura boundary-ku fallback kandippa varum, transition skip pannaadhu.

Step 3

Suspense + useTransition

import { Suspense, lazy, useState, useTransition } from 'react';

const Dashboard = lazy(() => import('./Dashboard'));

export default function App() {
  const [page, setPage] = useState('home');
  const [isPending, startTransition] = useTransition();

  function openDashboard() {
    startTransition(() => {
      setPage('dashboard');
    });
  }

  return (
    <>
      <button onClick={openDashboard}>
        Open dashboard
      </button>

      {isPending && <p>Updating...</p>}

      <Suspense fallback={<p>Loading dashboard...</p>}>
        {page === 'dashboard' ? <Dashboard /> : <p>Home page</p>}
      </Suspense>
    </>
  );
}
  • useTransition() update-ah non-urgent-nu mark pannum.
  • Already reveal aana content (“Home page”) transition pending-la irukkumbodhu screen-la-ye irukkum.
  • isPending vechu optional-ah “Updating...” maadhiri chinna indicator kaattalaam.
  • Suspense fallback-um transition pending UI-um related, aana different concepts.

Watch out

Common mistakes

1 · Suspense illaama lazy()

Lazy component suspend aagumbodhu mela oru Suspense boundary kandippa irukkanum.

2 · Boundary romba mela / keezha

Romba mela: full page blank. Romba keezha: spinners everywhere. Loading experience yosichu vainga.

3 · Tiny delay-ku periya spinner

Flash maadhiri theriyum. Same size skeleton use pannunga, illa ondrum kaattaadheenga.

4 · Fallback udane vandhu-poidum-nu nenaikkradhu

React reveal-ah throttle pannum. Fast-ah load aagura code-ku suspend pannaama placeholder-ah neengale kaattunga (article fix: ~200 ms faster).

5 · useTransition = Suspense-nu confuse

Transition = update priority. Suspense = loading boundary. Rendum serndhu work pannum, aana onnu illa.

6 · Ella async-ayum Suspense handle pannum-nu

lazy(), use(), Suspense-ready frameworks mattum. Normal useEffect fetch-ku Suspense trigger aagaadhu.

Bad

50 ms load-ku full-page spinner: flash, layout jump.

Good

Page apdiye irukkum; loading aagura card-la mattum same-size skeleton.

“Lazy loading component-ah load pannum; Suspense loading state-ah handle pannum. Transition use pannumbodhu already visible content smooth-ah maintain panna React-ku help kidaikkum.”

Interview answer (30 sec)

React.lazy splits a component into its own chunk and loads it on first render. While it loads, the nearest Suspense boundary shows its fallback. React throttles revealing suspended content, at most once every 300 ms after a fallback appears, to avoid flicker, so even fast code can wait. useTransition keeps already-visible content on screen during updates instead of showing a fallback, but it doesn't skip the fallback of a boundary mounting for the first time.
