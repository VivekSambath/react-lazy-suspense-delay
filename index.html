React.lazy() + Suspense

How does the fallback work when a component is lazy-loaded?

✂

Code splitting

Split one big bundle into smaller chunks.

⤓

Lazy loading

A component's code loads only when it's needed.

⏳

Suspense fallback

Shows a temporary UI while the code loads.

⏱

Delayed reveal

Even when the code is ready, React may hold back the reveal. That's the article's main point.

Based on “React.lazy, Suspense and the Hidden 300 ms Delay” by Matthew Wong (Tab Widgets, 29 Oct 2026). Use ← → or Space to move.

  • Normal import: the regular module path. Dashboard's code ships in the main bundle and loads at startup.
  • lazy(): React loads the module only the first time it renders the component.
  • With bundler support (Vite, webpack, Rspack) it becomes a separate chunk, so the first download is smaller.

Step 2

What is Suspense?

import { Suspense, lazy } from 'react';

const Profile = lazy(() => import('./Profile'));

function App() {
  return (
    <Suspense fallback={<p>Loading profile...</p>}>
      <Profile />
    </Suspense>
  );
}
  • lazy() loads the component's code.
  • Suspense is a boundary: “if anything inside is waiting, show this.”
  • fallback is the temporary UI shown while the lazy component waits.
  • Once the component is ready, React shows the actual component.

The article's main point

The code is ready, but the reveal isn't immediate

In Tab Widgets, widget code was ready at ~100 ms, but the widgets only appeared at ~380 ms.

Why the wait? React reveals suspended content at most once every 300 ms, counted from when a fallback was last shown (FALLBACK_THROTTLE_MS). It's intentional, to avoid flicker. It's a throttle, not a fixed delay for every component: if the code arrives after 300 ms, there's no extra wait.
Transition vs normal: when a transition updates content that's already visible, React keeps the old content on screen (no fallback flash). But a boundary that mounts for the first time still shows its fallback; a transition can't skip it.

Step 3

Suspense + useTransition

import { Suspense, lazy, useState, useTransition } from 'react';

const Dashboard = lazy(() => import('./Dashboard'));

export default function App() {
  const [page, setPage] = useState('home');
  const [isPending, startTransition] = useTransition();

  function openDashboard() {
    startTransition(() => {
      setPage('dashboard');
    });
  }

  return (
    <>
      <button onClick={openDashboard}>
        Open dashboard
      </button>

      {isPending && <p>Updating...</p>}

      <Suspense fallback={<p>Loading dashboard...</p>}>
        {page === 'dashboard' ? <Dashboard /> : <p>Home page</p>}
      </Suspense>
    </>
  );
}
  • useTransition() marks an update as non-urgent.
  • Content that's already revealed (“Home page”) stays on screen while the transition is pending.
  • Use isPending to show an optional small indicator like “Updating...”.
  • The Suspense fallback and the transition's pending UI are related but different concepts.

Watch out

Common mistakes

1 · lazy() without Suspense

A lazy component that suspends needs a Suspense boundary above it.

2 · Boundary too high or too low

Too high: the whole page goes blank. Too low: spinners everywhere. Place it with the loading experience in mind.

3 · A big spinner for a tiny delay

It looks like a flash. Use a same-size skeleton, or show nothing at all.

4 · Assuming fallbacks come and go instantly

React throttles reveals. For code that loads fast, show the placeholder yourself instead of suspending (the article's fix: ~200 ms faster).

5 · Confusing useTransition with Suspense

Transition = update priority. Suspense = loading boundary. They work together, but they aren't the same thing.

6 · Expecting Suspense to handle every async task

Only lazy(), use() and Suspense-ready frameworks. A normal useEffect fetch doesn't trigger Suspense.

Bad

A full-page spinner for a 50 ms load: a flash and a layout jump.

Good

The page stays put; only the loading card shows a same-size skeleton.

Recap

Quick summary

lazy()Loads a component's code when it's needed.
SuspenseDefines the fallback UI for suspended content.
fallbackTemporary loading interface.
useTransition()Marks updates as non-urgent and helps avoid loading flashes during transitions.
“Lazy loading loads the component; Suspense handles the loading state. With a transition, React can keep already-visible content on screen smoothly.”

Interview answer (30 sec)

React.lazy splits a component into its own chunk and loads it on first render. While it loads, the nearest Suspense boundary shows its fallback. React throttles revealing suspended content, at most once every 300 ms after a fallback appears, to avoid flicker, so even fast code can wait. useTransition keeps already-visible content on screen during updates instead of showing a fallback, but it doesn't skip the fallback of a boundary mounting for the first time.
